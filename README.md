# キャラ服資料館

「このキャラなら何を着る？」を考えるための、創作者向けファッション資料サイトです。通販ではなく、年代・生活・シーン・テイストからブランドとコーデ例を調べ、キャラクター専用の資料ボードへまとめる用途に特化しています。

## 主なページ

- `/search` — 自由入力と構造化条件による、完全一致コーデ候補・ブランド資料の検索
- `/outfits` — 年代・生活段階・職業・シーンを横断するコーデ処方箋。初期12件を表示し、必要な分だけ段階的に展開
- `/brand-map` — 価格帯×テイストのブランドマップ
- `/compare` — 最大4ブランドの比較、Markdownコピー、印刷
- `/brands/[slug]` — ブランド詳細、公式サイト、コーデ例、編集根拠
- `/board` — 最大12キャラクターを端末保存し、各キャラクターのブランド最大4件、コーデ最大6件、理由とメモを1枚に集約
- `/updates` — 更新情報。履歴は `data/updates.json` で管理
- `/help` — 検索・比較・保存・テーマ切替の使い方とFAQ

右上の共通メニューから更新情報、ライト／ダークモード切替、Helpへアクセスできます。トップは写真・イラストを使わず、タイポグラフィ・ブルーとライムの配色・CSSの余白と罫線で構成しています。人物像検索と収録資料への導線を最初の画面に配置しています。資料図機能は2026年9月26日に削除しました。コーデの文章資料・作画メモ・描写メモ・ボードは引き続き利用できます。

## キャラクターボードの保存

ボードはログイン不要で、ブラウザの `localStorage` に最大12キャラクターまでv2ライブラリ形式で保存します。旧v1形式で保存された1件のボードは、初回読み込み時に内容を保ったままv2ライブラリへ自動移行します。

共有URLには選択中の1キャラクターだけを、`#board=` 以降へUTF-8 Base64URL形式で格納します。共有URLからの取り込みは新しいキャラクターとして追加され、端末内の既存キャラクターを上書きしません。URL内のボード内容はHTTPリクエストの検索条件としてサーバーへ送られません。

`localStorage` は端末とブラウザに依存する一時的な保存先です。閲覧データの削除、ブラウザの変更、端末の故障や機種変更では保存内容を失う可能性があります。長期保存したいキャラクターは、ボード画面の「Markdownをコピー」「共有URL」または「印刷」も併用してください。

## 検索結果の信頼性

検索は入力を年齢・学齢・性別・季節・シーン・テイスト・職業・編集キーワードへ分解し、すべての判定項目に登録根拠があるブランドだけを表示します。条件を追加したときに候補が増えないAND方式です。順位は人気や実際の着用率ではなく、同じ登録コーデ内で構造条件を満たす根拠、ブランド情報の直接一致、個別コーデの一致、編集キーワードの順に重み付けした当館内の比較です。

検索結果の先頭には、選択した年代・学齢・性別・季節・シーン・テイスト・職業を1つの登録コーデ内で同時に満たす候補を最大6件表示します。主要アイテム、配色、シルエット、参照ブランド、ボード保存へ直接進めます。完全一致がない場合も条件を自動で緩めず、未登録であることを明示します。同じ条件は職業を含めてコーデ資料集へ引き継げます。

ブランド結果カードには一致項目数、根拠の種類、同時一致コーデの有無、注意点、編集日、情報確度、詳細ページの出典リンクを表示します。未知語、矛盾する年齢と学齢、範囲外の年齢は黙って補完せず、検索画面で明示します。年代・人物像・テイストは公式サイトの掲載内容を参考に編集部が整理した目安であり、ブランド公式の推奨ではありません。

## データ追加

- ブランド: `data/brands.json`
- 基本コーデ: `data/outfits.json`
- 拡張コーデ: `data/outfits-*.json`
- 更新情報: `data/updates.json`
- 全コーデ結合データ（自動生成）: `data/outfits.generated.json`
- ボード用軽量ID索引（自動生成）: `data/catalog-index.json`

ページはJSONから生成されます。slug／IDは重複させず、コーデの `brandSlugs` には登録済みブランドだけを指定してください。`data/outfits-任意の名前.json` を追加すると、全コーデ結合データと軽量ID索引が `dev` / `build` / `test` / `verify` の前に自動生成されます。

ページ内に写真・イラストなどの画像は使用しません。操作を示すLucideアイコンと、既存のサイトアイコン・共有用メタデータは維持しています。

同期、データ分類、参照ID、画像を使わないトップ画面、公式URLの整合性は `tests/rendered-html.test.mjs` で検査します。

## 開発

Node.js `>=22.13.0`。

```bash
pnpm install
pnpm dev
pnpm verify
```

`pnpm verify` は型検査、ESLint、本番ビルド、SSR HTML／データ整合性テストを順番に実行します。

## 技術構成

Next.js / TypeScript / Tailwind CSS / Lucide Icons / vinext / Cloudflare Workers。`.openai/hosting.json` がSitesの公開設定を保持します。

## GitHub Pagesへの公開

公開URLは<https://tetoriapot.github.io/chara-fuku-archive/>です。`.github/workflows/pages.yml`で、`main`の更新時に検証・静的ビルド・公開を実行します。GitHubのSettings → Pages → Sourceは「GitHub Actions」に設定します。

GitHub上ではソースを`deployment-source.zip`にまとめています。ワークフローはビルド時に展開し、検証済みの`out/`だけを公開します。リポジトリへの自動書き込みは行いません。通常のソース一式と`package.json`がリポジトリ直下にある場合は、ZIPを使わずにビルドします。

ローカルの変更をコミットした後、次のコマンドで更新用ZIPを作成できます。GitHubの「Add file → Upload files」で同名ファイルを置き換えると、公開処理が始まります。

```bash
git archive --format=zip --output=outputs/deployment-source.zip HEAD
```

```bash
pnpm build:pages
pnpm test:pages
```

`build:pages`は既存のNext.jsで静的ファイルを`out/`へ生成します。GitHub Actionsでは`GITHUB_REPOSITORY`からURLとサブパスを決めます。別の公開先で使う場合は、`NEXT_PUBLIC_BASE_PATH`と`NEXT_PUBLIC_SITE_URL`を指定します。従来の`pnpm build`と`pnpm verify`はCloudflare向けのビルド・検証を継続します。

GitHub Pagesでは、検索・コーデ絞り込み・比較のURL条件をブラウザで読み取ります。ブランド詳細、検索条件の共有、比較、ボード保存、Markdownコピー、印刷、テーマ切替を引き続き利用できます。

端末保存はドメインごとに分かれるため、旧サイトのボードは新サイトへ自動移行されません。旧サイトでコピーした共有URLの`#board=...`を、新サイトの`/chara-fuku-archive/board/`末尾へ付けて開くと、既存の取り込み機能で保存できます。元のサイトにあるデータは変更しません。
